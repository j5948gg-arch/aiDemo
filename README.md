# 九路棋盤・連線版

零依賴的 Node.js 伺服器（只用 Node 內建模組），不需要 `npm install`。所有走法都由伺服器驗證。

## 啟動

```
node server.js
```

然後用瀏覽器開 http://localhost:3000

## 一個人測試兩位玩家

- 用兩個不同的瀏覽器（例如 Chrome 和 Edge）各開一次；或
- 同一個瀏覽器：第一個分頁開 `http://localhost:3000`，第二個分頁開 `http://localhost:3000/?p=2`（`?p=` 後面的字會當成另一位玩家的身分）。

兩位玩家要用不同的 ID。同一個 ID 在兩處同時登入，先登入的那一邊會被擠掉。

## 同一個 Wi-Fi 的其他裝置

查出你電腦的區網 IP（例如 192.168.1.20），其他裝置開 `http://192.168.1.20:3000`。若連不上，請檢查電腦防火牆是否允許 Node.js。

## 換棋子圖片

圖檔放進 `public/img/`，再到 `public/rules.js` 最上面的 `TYPES`，把該棋子的 `image` 改成 `'/img/檔名.png'`。`name` 是右邊文字框顯示的全名，`tags` 是標籤。改完重新整理網頁即可，不用重啟伺服器。

## 自動測試

```
npm test
```

需要 Node 22 以上。依序執行：規則單元測試（`test/rules.js`）、AI 測試（`test/ai.js`：四個等級都給出合法動作、會吃白送的子、超高階勝過初階）、資料測試（`test/data.js`：500 題全部合法、抽驗殺王題重新求解、五局回放與紀錄一致）、連線測試（`test/e2e.js`：登入、開房、上鎖、隨機對弈、斷線重連、四間 AI 房都會回應、棋鐘）。

## 上線給所有人玩

需要一個支援 WebSocket 的主機（例如 Render、Railway、Fly.io 或自己租的 VPS）。

1. 把整個資料夾放上主機，啟動指令是 `node server.js`。伺服器會讀環境變數 `PORT`。
2. 請使用 HTTPS 網址（多數平台會自動提供）。網頁會自動改用加密的 `wss://` 連線。
3. 玩家的 ID 登記存在 `data/players.json`。如果主機的磁碟在重新部署後會被清空，要設定持久磁碟，並用環境變數 `DATA_DIR` 指向它，否則已登記的 ID 會消失。
4. 網域不是必要的，平台會給你一個免費的子網址；想要好記的網址再另外買網域並指過去。

各平台目前的免費方案與限制請以官方說明為準。

## 棋鐘與計分

- 每位玩家有「每手 8 秒」和「自由時間 301 秒」。每手的 8 秒用完後，才開始扣自由時間；某一方的自由時間燒完，遊戲就結束。
- 當雙方棋子（含王）都只剩 7 顆以下時，每手縮為 3 秒。
- 開局有 5 秒緩衝，才開始計白方的第一手。
- 斬擊確認、復活選棋、復活放置，都各算一個新的決定，會重新給時間，由要做決定的那一方計時。
- 時間到之後依雙方剩餘棋子算分，分數高的獲勝，同分為和局：
  - 自由時間沒有燒完的一方，先加 10 分。
  - 咚 10 分；OL、孩子多 8 分；抹茶小紅豆 7 分；夜王 5 分；龍 2 分；王 0 分；其餘（熨斗、鞋子、量產型戰士、OTL、謎之美少女）各 3 分。
- 計時與結算都在伺服器進行。想改秒數，可用環境變數 `CHESS_MOVE_MS`（每手毫秒數）、`CHESS_FREE_MS`（自由時間毫秒數）、`CHESS_GRACE_MS`（開局緩衝毫秒數）、`CHESS_FAST_MS`（殘局每手毫秒數，預設 3000）。計分表在 `public/rules.js` 的 `SCORE`。

## 規則（已取消將軍限制）

- **王可以被吃**：吃王即獲勝。不再有「被將軍必須化解」「不能送王」「將死」「無路可走判分」。王受威脅時，畫面只顯示提示「⚠ 王受威脅」，不限制走法。
- **無棋可走**：只是跳過該方回合；雙方都無棋可走則和局。
- **禁止著法（長將、長殺、長捉）**：同一個局面（同一方要走）出現第 3 次時裁決，看「上次出現到現在」那段循環中，雙方每一手是否都帶著同一種威脅：
  - 長將：每一手都能吃對方的王。長殺：每一手都能一次消滅 2 子以上（咚斬擊、孩連鎖）。長捉：每一手都能吃同一顆有價值的子（目標比攻擊者值錢，或吃完攻擊者不會被回吃）。
  - 只有一方違規：違規方必須變著，不變就判負。雙方都違規或都沒違規：和局。
- **剛復活的棋子**：不能吃棋；剛復活的咚可以移動，但不能吃棋也不能斬擊。
- **投降**：隨時可按「投降」（需要連按兩次確認），對方獲勝。

## AI 練習室

大廳固定有四間房：「初階AI練習室」「中等AI練習室」「進階AI練習室」「超高階AI練習室」，每間一次一位玩家，進房後隨機分配黑白。對局結束或玩家離開後，房間自動回到等待狀態（玩家離線超過 5 分鐘也會重置）。

- **初階**：一半的時候亂走，其餘只看一步（吃得到就吃）。
- **中等**：搜尋 2 手，偶爾走次佳著法。
- **進階**：限時內逐步加深到最多 6 手。
- **超高階**：迭代加深（最深 14 手）、alpha-beta 剪枝、置換表、吃子延伸的靜態搜尋、殺手與歷史啟發式；會避免走回已出現過的局面。
- 四款都會避開「照走就因禁止著法而判負」的走法。AI 下棋前會停頓 `CHESS_BOT_DELAY_MS`（預設 700）毫秒；思考時間不超過當手剩餘時間的 40%（初階 150 ms、中等 400 ms、進階 1.5 s、超高階 3 s 為上限）。
- AI 在獨立的 worker 執行緒（`ai-worker.js`）思考，不會卡住主執行緒。主機只有一顆 CPU 時，同時有很多人對戰超高階仍會互相拖慢。
- **進階 AI 的修正**：原本的進階 AI 在根節點用 `-alpha` 當搜尋視窗，結果所有根著法的分數都變成一樣，等於隨機亂走（白送的子也只有約 1/20 的機率去吃）。已改成根節點完整視窗搜尋，現在白送的子會吃。這是行為變動，若要還原請看 `ai.js` 中標有註解的那一行。

## 題庫、高手對決、教學

首頁最上方的導覽列有四個分頁，後三個不需要登入：

- **🧩 題庫**：500 道殘局（每方最多 7 顆棋子）。題型是「殺王」（一手／兩手／三手內強制吃王，共 180 題）與「贏子」（找出最佳著法，共 320 題），難度 1 到 5 星。點棋子再點目的地作答，答對才算解出，可以按「提示」「看解答」。斬擊與復活步驟自動選最佳處理。每一題都經過求解器驗證：殺王題由搜尋找出「最短幾手能強制吃王」與所有達成的首著（最多 2 個），並確認主變可以重播到吃王；贏子題要求最佳著法在 3 手與 4 手搜尋下相同，且領先第二名至少 2 分（搜尋有節點上限，所以是「在搜尋範圍內」唯一最佳）。題目是隨機產生的殘局，不是名局。
- **🏆 高手對決**：5 局超高階對超高階、真的吃到王的對局（由 `tools/import-replays.js` 從對局文字檔匯入），可以播放、暫停、上一手、下一手、拖曳進度、調速度（快捷鍵：← → 換手、空白鍵播放／暫停），並附每一手的棋譜與子力曲線。
  換成別的五局：`node tools/import-replays.js <對局.txt>`（文字檔就是 `tools/local-gen.js` 輸出的 `.txt`；工具會用規則引擎把棋譜還原成動作，並逐行比對，不一致就報錯），在 `tools/replay-texts.js` 替每局補上標題與說明，最後 `npm run build-data`。
- **📚 教學**：基本玩法、12 種棋子的走法圖解、戰術規律與公式（每條都標明依據是數據、規則推導或未證實的嘗試，並附樣本數）。

資料檔在 `public/data/`（`puzzles.json`、`games.json`、`learn.json`），由 `tools/` 下的腳本產生：

```
npm run selfplay     # 100 局超高階自我對弈 → data/selfplay.jsonl（可中斷續跑）
npm run analyze      # 統計、挑出 5 局、學習評估權重 → data/analysis.json 等
npm run puzzles      # 產生題庫（可重複執行，累積到 500 題）
npm run build-data   # 驗證並輸出 public/data/*.json
```

**自我對弈的限制**：每手只思考 0.09 秒、180 手上限（98 局到上限後依分數判定，只有 2 局真的吃到王），並不等於真實棋鐘下的對局。**評估權重的學習沒有成功**：學到的權重在對戰驗證中沒有勝過原本的（39.6%，折衷版 52.1%，各 24 局），所以超高階仍使用原本的點數表；要啟用學到的權重，把 `{"w":[...]}` 存成 `ai-weights.json` 即可。

## 運作方式與限制

- **固定 ID**：第一次登記 ID 時，瀏覽器會產生一組隨機金鑰存在本機，伺服器只記金鑰的雜湊。之後同一個瀏覽器自動認得你；換瀏覽器或清除瀏覽資料後，就無法取回那個 ID。
- **房間密碼**：伺服器端檢查，密碼雜湊後存在記憶體裡。
- **房間**只存在伺服器記憶體，重啟後消失。玩家離線後可用同一個 ID 重新連線，會自動回到對局。
- 尚未實作：觀戰、防洗頻限制。

## 檔案

- `server.js`：HTTP 靜態檔案、WebSocket、房間與玩家管理、AI 房間。
- `ai.js`：四款 AI 的入口（初階／中等／進階）；`ai-super.js`、`ai-eval.js`：超高階的搜尋與評估；`ai-worker.js`：AI 的 worker 執行緒。
- `tools/`：自我對弈、分析、題庫求解與產生、資料驗證與輸出。
- `public/learn.js`：題庫、回放、教學的介面；`public/data/`：題庫、五局回放、教學資料。
- `public/rules.js`：棋子設定與全部規則，瀏覽器和伺服器共用。
- `public/index.html`：網頁畫面。
- `test/e2e.js`：端對端測試。
